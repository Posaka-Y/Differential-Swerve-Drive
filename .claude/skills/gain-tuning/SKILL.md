# 差動ステア ゲイン調整パイプライン

NUCLEO-G474RE上の閉ループベンチテスト(+10°ステップ応答)を使い、
`firmware/src/main.c` の `control_config` を1パラメータずつ変えて応答を改善する反復作業。

## 絶対安全ルール(違反禁止)

1. **`current_limit` を2000より上げない。** 上げる判断はユーザーのみ。
2. **`steer_mode_ki` / `drive_mode_ki` を150以上にしない。** Ki=200で±2°の激しいリミットサイクル発振を実測済み(2026-07-05)。
3. 発振(下記判定基準)を検出したら、**直ちに直前の安定値へ戻して書き込む**。解析や報告はその後。
4. 発振が起きた後の次の試験で角度が大きく逆走・発散した場合、機構破損の可能性がある。
   **それ以上の通電試験を止め、ユーザーに手回し点検を依頼する。**
5. 1イテレーションで変えるパラメータは原則1つ。
6. セッション終了時・中断時は `CLOSED_LOOP_TEST_ENABLED = 0` に戻して書き込み、安全待機で引き渡す。
7. ユーザーから「機構がおかしい」等の報告があれば即 `CLOSED_LOOP_TEST_ENABLED=0` で書き込み。

## テストファームの仕様(firmware/src/main.c)

- 起動後、AMT22とC620フィードバックが揃った時点で**自動的に1回だけ**試験開始
  (目標 = 起動時角度 +10°、wheel=0rpm)。
- B1押下・センサ異常・C620途絶・角度誤差12°超で停止しラッチ(リセットまで再開しない)。
- 書き込み(flash.ps1)がリセットを兼ねるので、書き込み=新しい試験の開始。
- `CLOSED_LOOP_TEST_ENABLED` 1で駆動、0で安全待機(電流常時0)。試験中は1にする。
- 250ms周期でVCP(COM15, 115200)へログ:
  `run= angle= target= err= steer= m1=実rpm/目標 i1= m2=…i2= steerMode=目標/実測 iSteer= driveMode=目標/実測 iDrive=`
  (角度系はミリ度、電流はmA相当、iSteer/iDriveはモード電流のミリ表記)

## 1イテレーションの手順

1. `firmware/src/main.c` の `control_config` を1箇所編集する。
2. **先に**シリアル監視をバックグラウンド起動:
   ```powershell
   & "firmware/scripts/serial-monitor.ps1" -Port COM15 -DurationSeconds 15 -EarlyExit
   ```
   `-EarlyExit` は今回の試験の収束(|err|<500 かつ steer=0 が4サンプル連続)または
   `STOP:` 行を検出すると約2秒後に自動終了する(イテレーション短縮)。
   15秒は安全上限として残す。接続後5秒以内のSTART行はVCPバッファ再生の古い
   データとして無視するため、flashが5秒未満で完了した場合は早期終了せず
   15秒フルで走るだけ(誤検出はしない)。従来挙動は `-EarlyExit` なしで維持。
3. 書き込み: `& "firmware/scripts/flash.ps1"` (ビルド込み。verify/reset成功を確認)
4. 監視完了を待ち、出力ファイルを解析する。
5. 判定(下記)に従い次の編集を決める。結果を必ず記録する(下記「記録」)。

## ログ解析の注意(重要)

- **ST-LINK VCPは未接続期間のデータをバッファし、モニタ接続時にまとめて再生する。**
  ログ先頭には前回ファームの古い行が混ざる。**新しい試験の `START: angle=X target=X+10000`
  行より前は捨てる。** targetが「今回の起動角+10°」と一致することを必ず確認。
  一致しないtargetの行は全て古いデータ。
- 行の途中で切れた行(スプライス)は無視する。

## 判定基準

- **収束成功**: `err` が単調(多少の停滞可)に減少し、|err| < 500(0.5°)で `steer=0` になり静止。
  収束時間 = STARTから静止までのログ行数 × 0.25s。
- **発振(即revert)**: `err` の符号が交互に反転し |err| > 1000 を繰り返す、
  または `i1`/`i2` が ±limit 近傍を交互に往復する。
- **スティックスリップ停滞**: 同じangleのまま `i1`/`i2` だけ増加する区間。
  0.5〜1秒程度は許容。長い場合はKi(≤150)か `steer_min_rpm` を検討。
- **発散停止**: `STOP: angle diverged` はログに明記される。直前の変更をrevert。

## パラメータ表(2026-07-06時点)

| パラメータ | 安定実績値 | 備考 |
|---|---|---|
| steer_mode_kp / drive_mode_kp | 5.0 | 未探索。上げる場合は+50%ずつ |
| steer_mode_ki | 125.0 | **確定値**。100→125で改善(3.25s→3.0s、誤差0.37°→0.02°)、150は125より悪化(Ki=100相当まで後退)。200は発振NG |
| drive_mode_ki | 100.0 | wheel=0の操舵試験では未検証。駆動実走試験時に個別に125を試すこと |
| steer_max_rpm | 5.0 | 計画値。これ以上はユーザー承認 |
| steer_min_rpm | 2.0 | スティックスリップ帯(~1rpm以下)回避の速度フロア |
| steer_accel_rpm_per_s | 50.0 | 減速の効きに影響 |
| angle_kp_rpm_per_deg | 0.5 | |
| angle_deadband_deg | 0.5 | 狭めると終端ハンチングのリスク |
| mode_rpm_filter_tau_s | 0.02 | |
| current_limit | 2000.0 | **上限固定**(実測ブレークアウェイ最大950の約2倍) |
| mode_integral_limit | 1200.0 | 2026-07-06に実機再現確認済み(挙動差なし)。**950未満にしない**(静止摩擦に勝てなくなり永久固着する)。挙動切り分け時は2000で実質無効化 |
| wheel_accel_rpm_per_s | 200.0 | 2026-07-06導入、未実測。wheel=0の操舵テストには影響しない |

ベスト実績(2026-07-06構成、steer_mode_ki=125): 10°ステップを約3.0秒、
終端誤差0.02°、軽微なオーバーシュート(1サンプルのみ-0.107°)。

## 機構の既知特性

- 静止摩擦のブレークアウェイ電流は角度・方向依存で150〜950mA(実測)。
  摩擦フィードフォワードは使わない方針(積分のみで吸収)。設計経緯は
  `firmware/docs/CONTROL_LOOP_TUNING.md` 参照。
- 指令速度が低い(ステア~1rpm以下)とスティックスリップのリミットサイクルに入る。
  `steer_min_rpm` のフロアで回避している。
