# 単一モジュール評価計画(負荷ロバスト性検証)

作成: 2026-07-26(状態: 方針確定、治具製作・計測は未着手)

## 目的

差動ステアユニット1基について、ステア収束速度・ホイールrpm挙動が理論値に近く、かつ負荷変動でロバスト(挙動が変化しない)であることを検証する。ここで確立した制御・評価手法を土台に、`control/CENTRAL_COORDINATED_CONTROL.md`の3輪協調(高レイヤーからのwr/ws配信)と`control/LOAD_ADAPTIVE_CONTROL_ROADMAP.md`の負荷適応制御へ接続する。

## なぜモジュール単体評価が難しいか

差動ステアは1モータの出力がwheel/steer両方に同時に効く(`DRIVE_RATIO=32/11`, `STEER_RATIO=8/11`)ため、独立スイーブモジュールと異なり「steerだけ」を機構的に切り離して評価できない。負荷試験・評価軸はこの前提で設計する。

## 治具方針

検討した3案と採否:

| 案 | 採否 | 理由 |
|---|---|---|
| 実機3モジュール同時稼働 | 不採用 | 3輪相互干渉で異常原因を切り分けられない。独立評価にならない |
| 単輪+台車+重り | 不採用 | 荷重印加が不安定で治具として成立しにくい |
| **4隅従動輪+中央に評価対象モジュール1基** | **採用** | 荷重がシャーシ経由で接地点に伝わり実機に近い。駆動は1モジュールのみで独立評価を維持でき、重り位置で荷重段階も作れる |

5点接地(駆動1+従動4)は静定性に懸念があるため、従動輪側に多少のコンプライアンス(バネ等)を持たせて全点接地を保証する。重り自体は水・米袋等、精密な分銅である必要はない。

## 動作包絡線(理論値・マージン)

モータ定格469rpm(M3508+C620出力軸)、`n_drive = 2.909×(n1-n2)/2`, `n_steer = 0.727×(n1+n2)/2` から、2モータの共有電流予算による結合包絡線を導出する(`|n1|,|n2| ≤ 469`の正方形制約領域が、差動の線形変換で菱形に写る)。

理論境界:

$$
\frac{|n_{drive}|}{1364} + \frac{|n_{steer}|}{341.1} \le 1
$$

マージン10%を適用した目標境界(係数を0.9倍):

$$
\frac{|n_{drive}|}{1228} + \frac{|n_{steer}|}{307.0} \le 1
$$

| 動作パターン | 理論値 | 目標値(90%) | 備考 |
|---|---|---|---|
| 純駆動(steer=0) | 1364 rpm | 1228 rpm | 実測1200rpm(2026-07-07 wheel定常試験, p-p 3.5〜4rpm)とほぼ一致。マージンの妥当性を裏付け |
| 純操舵(drive=0) | 341.1 rpm (2047°/s) | 307.0 rpm (1842°/s) | 現行ソフト上限`steer_max_rpm`=40rpm(240°/s)は理論比12%・目標比13%で大幅に余裕あり |
| 片側モータのみ(n1=469, n2=0) | 682 rpm / 170.5 rpm (1023°/s) | 614 rpm / 153.4 rpm (921°/s) | 理論境界上に乗る参照点。`control/KINEMATICS_AND_RPM.md`の数値例と一致 |
| wheel運用下限 | 75 rpm | — | 40rpmはstick-slipで不可と実測済み(2026-07-07) |

**steer軸の実運用目標は理論マージンでなく競技要求から決める。** 理論値に対してすでに桁違いの余裕があり、包絡線側が制約になる状況ではないため。

## 制御ループ周期(実装済み・追加作業不要)

ユニットMCU側は`CONTROL_PERIOD_MS=1`(`firmware/src/main.c`)で1kHz制御ループが既に実装済み。これはC620自体のCANプロトコルが1kHz固定(指令送信・フィードバック受信とも)であることに整合しており、これ以上ユニット側ループを速くしても実効更新レートは伸びない。C620内部の(非公開・高速な)電流ループ + ユニットMCUの1kHz速度/位置ループ、というカスケード構成がすでに成立している。**残る改善余地はデジタルループ速度ではなく機構帯域(バックラッシュ・摩擦)側にある。**

## 計測項目

### 0. wheel rpm計算値の信頼性確認(最初に実施)

steer固定(純駆動、n1≈-n2)の条件で、モータエンコーダ由来のwheel rpm計算値(`feedback.rpm / 19 × DRIVE_RATIO`)が実際の出力軸rpmと一致するかを検証する。無負荷・負荷双方で実施。

- 問題なければ、以降はモータエンコーダ由来の値を信頼して進める(外部計装は不要)
- 問題があれば、出力軸に外部エンコーダ(`AMT102`仮設。オドメトリ基板採用品と同型・同ファームパターン=TIM Encoder Modeを流用)を追加する

この確認はsteer固定・純駆動条件でのみ妥当性を保証する。steer同時動作時のバックラッシュ挙動までは保証しない点に注意。

### 1. 負荷試験本体で記録する状態量

- wheel rpm(モータエンコーダ由来、0で信頼性確認済みのもの)
- steer角度(AMT222、出力側直結のため既に信頼できる)

### 2. 電気量

- `torque_current`(C620フィードバック。`c620.c`でデコード済みだが現状`main.c`のログには出力していない。追加が必要)
- `temperature_c`

負荷時に電流飽和で頭打ちになっていないか、ゲイン不足と切り分けるために必須。

### 3. 試験条件の振り方

- wheel目標rpm: 複数点(75 / 500 / 1200 rpm 等、既存ログの条件を踏襲)
- steer目標角度Δθ: 複数段階(小角度 〜 90° 〜 180°)
- 荷重レベル: 無 / 軽 / 重 の複数点(「変化なし」を主張するには最低2点比較が必要)

### 4. 評価する量

- 各条件の整定時間・オーバーシュート・定常p-p(wheel, steer双方)
- 片方をステップさせた際、もう片方に生じる乱れ量(クロスカップリング)
- 上記すべての**無負荷条件との差分**(絶対値でなく「負荷でどれだけ劣化したか」が本題)

## 実施順序

1. steer固定でのwheel rpm信頼性確認(無負荷・負荷)
2. 独立軸試験(無負荷) — 大部分実施済み(`PROGRESS.md`の2026-07-07試験群を参照)
3. 同時指令試験(無負荷、治具不要) — クロスカップリングデータ取得。既存NUCLEOベンチのまま、指令の出し方を増やすだけで着手できる
4. 4隅従動輪治具の製作
5. 負荷試験本体(2・3を負荷条件で再実施し、無負荷との差分を評価)

3は差動の合成数式そのものに起因する現象で負荷に依存しないため、4(治具製作、時間がかかる)を待たずに着手できる。
