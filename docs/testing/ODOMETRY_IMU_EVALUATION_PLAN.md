# オドメトリ+IMUモジュール評価計画

作成: 2026-07-26(状態: 方針確定、治具製作・計測は未着手)

## 目的

オドメトリ基板(3輪AMT102 + ICM-42688-P、unitId=4)が算出するpose(x/y/θ)の精度を検証する。`electrical/ODOMETRY_BOARD_REQUIREMENTS.md`で定義済みの配信仕様(pose 100Hz、健全性10Hz)を前提に、その数値の妥当性の裏付けと、センサフュージョンの重み付け方針を確定する。

## ホイール構成

AMT102 x3のうち2輪は平行配置、1輪は独立(直交方向)配置。平行2輪ペアは「平均=前進」「差分/トレッド幅=回頭」という計算になっており、独立1輪が横方向変位を担う想定。

## 評価の2段階(2次元経路治具は不採用)

XY全体をトレースする2次元経路治具は製作難度が高いため不採用とした。代わりに、系統誤差(スケール・トレッド幅)を切り分けて評価する2つの単純な治具で代替する。曲線走行中の過渡的な誤差までは評価対象外とする。

| 試験 | 治具 | 検証する誤差 |
|---|---|---|
| 直線スライダー試験 | 定規+スライダー。各輪を既知距離だけ独立に往復させる | 各輪の線形換算精度(カウント数→距離のスケール誤差) |
| 回頭ピボット試験 | 固定ピボット+角度ゲージ(または旋回台)。既知角度だけ基板ごと回転させる | 平行2輪の差分計算に使うトレッド幅の校正誤差 |

直線試験だけでは回頭誤差は原理的に検出できない。平行2輪は直線移動中は常に同じだけ動くため差分が常時ゼロになり、差分計算に使うトレッド幅の設定値が間違っていても誤差が表に出ない。2試験を組み合わせて初めて、静的な系統誤差(スケール・トレッド幅)をカバーできる。

## IMUセンサフュージョンの重み付け方針

「勘で重みを決める」のではなく、各センサの誤差特性を先に測ってから重みを導出する方針とする。

- **ジャイロ(ICM-42688-P)ドリフト特性**: 静止状態でジャイロを積分し続け、時間あたりのθドリフト量を測定する。データシートのnoise densityとも突き合わせる
- **ホイールオドメトリのθ誤差特性**: 上記の回頭ピボット試験で、特にスリップが出やすい条件(高速回頭、路面条件)を振って誤差の出方を測る

両者の誤差特性(分散)が分かれば、相補フィルタの時定数やカルマンフィルタのR行列は計算で決まり、手動チューニングの範囲を最小化できる。

## 更新周波数の考え方

「精度」を2つに分けて考える。

1. **推定値そのものの精度**: 内部の積算(エンコーダカウント・ジャイロサンプリング)レートで決まる。デッドレコニングは微小変位の積分処理なので、サンプル間隔が粗いと並進+回頭が同時に起きる場面で円弧を直線近似する誤差が乗る。ここは既にTIM Encoder Modeで固定周期1kHzが仕様化済み(`ODOMETRY_BOARD_REQUIREMENTS.md`)であり、ハードウェアタイマ駆動でほぼコスト無しなので、これ以上の検討は不要
2. **消費側(Teensy)が使う値の鮮度**: central CANへの配信レートで決まる。消費側の車体逆運動学は100Hzで動く設計(`control/CENTRAL_COORDINATED_CONTROL.md`)なので、配信もこれに合わせるのが妥当。既存要件のpose 100Hz配信はこの理屈と整合している

ユニットMCUの1kHz制御ループはSET_TARGET追従用の別経路であり、オドメトリのデータを消費しないため、配信レートをそちらに合わせる理由はない。配信を100Hzより上げる場合も、Teensy自身が100Hzでしか制御判断を更新しないため、得られる効果は「Teensyが読みに行く瞬間の値の古さ」が最大10ms→数msに縮む程度の二次的なもので、優先度は低い。

## 実施順序

1. 直線スライダー試験(各輪独立、既知距離)
2. 回頭ピボット試験(既知角度)
3. ジャイロ静止ドリフト試験
4. 1〜3の結果からセンサフュージョンの重み(時定数/分散)を導出
