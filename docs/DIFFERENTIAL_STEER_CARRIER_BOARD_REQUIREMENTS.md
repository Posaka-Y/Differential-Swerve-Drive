# 差動ステアユニット基板 設計要件・注意点

> **注意: このファイルは旧版の詳細メモ。正本は `electrical/CARRIER_BOARD_REQUIREMENTS.md`。**
> 特に以下は正本側で結論が更新済みであり、本ファイルの記述は古い。
>
> - AMT22はデータシート確認済み(VIH min 2.0V、出力High 3.3V)。**全信号3.3V直結でよく、MISO分圧・バッファ・5Vトレラントピン要件は不要。**
> - LDOはAMS1117ではなくMCP1826S-3302を第一候補に変更。
> - **搭載ボードはNUCLEO-G474REで確定(2026-07-02)。G431KB前提の記述はすべて旧い。**
> - **中央通信はRS485ではなくCANで確定(2バスCAN構成)。** 本ファイルのRS485関連記述は不採用案の記録。

## 方式

NUCLEO-G431KB を載せるキャリアボード方式とする。

1ユニットの構成は以下。

| 要素 | 数量 |
|---|---:|
| M3508 | 2 |
| C620 | 2 |
| AMT22 | 1 |
| NUCLEO-G431KB | 1 |

## 0. 設計思想

- 各ユニットは自己完結した知能を持つ部品として扱う。
- 挿す位置を変えても同じファームで動く。ユニットIDだけを振り直す。
- ユニット内MCUで2モータ協調、方位ループ、速度ループを閉じる。
- 中央Teensyへは目標角と目標速のみを送り、ステータスは間引いて返す。
- リフローやQFNハンダを避けるため、MCU最小構成はNUCLEO-G431KBに任せる。
- キャリアボード側は手ハンダ可能な部品だけで構成する。
- 第一段階はキャリアボードで実証する。
- 第二段階として、必要になったら裸チップ基板へ移行する。

## 1. 外部インターフェース要件

ユニットが外部と接続する線は以下。

| 信号 | 電圧/種別 | 用途 | 備考 |
|---|---|---|---|
| 24V | 電源・大電流 | C620 x2 駆動 | XT30等、電流定格のあるコネクタ |
| 5V | 電源・小電流 | 制御系 | 中央分電盤で 24V から 5V に降圧済み |
| GND | 共通 | 基準、リターン | スターGNDの一端 |
| CAN_H / CAN_L | 差動信号 | 制御バス | 小信号コネクタ |

前提:

- 配線が短い前提で、中央集約降圧を採用する。
- 各ユニットからDC-DCとインダクタを省き、基板を小型化する。
- C620 x2 とのCAN接続、AMT22とのSPI接続はユニット内コネクタで受ける。

## 2. 電源系

### 構成

```text
6S LiPo x2
  |
  |-- 24V系メイン分電盤
        |-- 24V --> C620 x6
        |-- 24V --> DC-DC 24V->12V --> mini PC
        |-- 24V --> DC-DC 24V->5V  --> 中央Teensy / センサ / 各ユニット制御基板

各差動ステアユニット:
  24V --> C620 x2
  5V  --> キャリアボード
  5V  --> AMT22
  5V  --> LDO AMS1117-3.3 --> 3.3V MCU / CANトランシーバ
```

6S LiPo x2 は、基本的に同電圧のまま電流容量を増やす構成として扱う。直列接続すると12S相当、満充電で約50.4Vになり、C620系には危険。

可能な構成は以下。

| 構成 | 電圧 | 用途 |
|---|---:|---|
| 6S x2 並列 | 約22.2V、公称 | 推奨。C620 x6へ共通分配 |
| 6S x2 独立系統 | 約22.2V、公称 x2 | 左右・前後などで分ける場合。GND共通化に注意 |
| 6S x2 直列 | 約44.4V、公称 | 非推奨。C620に入れない |

### バッテリ差し替えと並列バランス

6S LiPo x2 を差し替えやすくする場合でも、単純な並列直結は避ける。

理由:

- 電圧差のあるLiPo同士を直結すると、大きな突入電流が流れる。
- 片方のバッテリからもう片方へ逆流する可能性がある。
- 差し替え時にC620やDC-DCの入力コンデンサへ突入電流が流れる。

推奨構成:

```text
6S LiPo A -- ヒューズ -- 逆流防止/理想ダイオード --+
                                                   +-- プリチャージ -- メインリレー -- 24Vバス
6S LiPo B -- ヒューズ -- 逆流防止/理想ダイオード --+
```

要件:

- 各LiPoの直後にヒューズを入れる。
- 2本のLiPoを並列化する前に、電圧差を確認できるようにする。
- 電圧差が大きい状態で並列接続しない。
- 逆流防止としてショットキーダイオード、または理想ダイオード回路を検討する。
- 大電流用途なので、発熱と電圧降下の小さい理想ダイオード方式が望ましい。
- メイン24Vバス投入前にプリチャージ経路を用意し、DC-DCやC620入力コンデンサへの突入を抑える。
- バッテリ交換用コネクタは、抜き差ししやすさより電流定格と接触信頼性を優先する。

運用ルール:

- 交換前にLiPo A/Bの電圧差を確認する。
- 電圧差が大きい場合は並列運用しない。
- 充電状態の異なるパックを混ぜない。
- 可能なら同型・同容量・同劣化度のパックをペアで使う。

制御系のユニット間ハーネスは、基本を4線にする。

```text
CAN_H
CAN_L
VIN_CONTROL
GND
```

ここで `VIN_CONTROL` は各ユニット制御基板へ配る5Vを指す。C620用の24V大電流ラインは、この4線とは別に太線で分配する。

### 注意点

- 6S満充電電圧は約25.2V。C620の絶対最大定格を超えないかデータシートで確認する。
- 6S LiPo x2 を直列にしない。直列時は満充電で約50.4Vになる。
- C620 x6 へは24V系をそのまま分配する。
- mini PC へは24Vから12Vへ降圧して供給する。
- 中央Teensy、センサ、各ユニット制御基板へは24Vから5Vへ降圧して分配する。
- 中央5V DC-DCは5V/3A以上を最低ラインとし、余裕を見て5A品を採用する。
- mini PC用12V DC-DCは、mini PCのピーク電力に合わせて別途選定する。
- 5VラインがAMT22の上限を超えないよう、レギュレーションの良いバックコンバータを選ぶ。
- AMS1117-3.3は、5V入力から3.3V出力なのでドロップアウト余裕はある。
- LDOとトランシーバ近傍には0.1uFを置く。
- LDO出力側には数uF以上のバルクコンデンサを置く。

### 非常停止

非常停止は、ソフト停止だけに依存せず、24V主電源を物理的に遮断できる構成にする。

基本構成:

```text
6S LiPo x2
  |
  |-- ヒューズ
  |-- メインリレー / DCコンタクタ
  |-- 24Vメインバス
        |-- C620 x6
        |-- 24V->12V mini PC
        |-- 24V->5V 制御系
```

要件:

- 非常停止ボタンでメインリレー、またはDCコンタクタのコイル電源を落とす。
- E-stop時はC620 x6への24V供給を遮断する。
- 可能なら24V->12Vと24V->5Vも同時に遮断する。
- ただしログ保存や通信停止処理を優先する場合は、制御系5Vだけ別系統で数秒保持する設計も検討する。
- リレー/コンタクタはDC遮断定格を確認する。AC用リレーを流用しない。
- C620 x6の最大電流と突入電流を見込んで接点容量を選ぶ。
- コイルにはフライバックダイオード、またはTVSを入れる。
- 非常停止信号はTeensyにも入力し、ソフト側でも即座にモータ指令をゼロにする。

推奨動作:

1. 非常停止ボタンが押される。
2. Teensyと各ユニットMCUがモータ指令をゼロにする。
3. メインリレー/コンタクタが開く。
4. C620への24V供給が遮断される。

安全側に倒すなら、非常停止ボタンはノーマリクローズ接点を使う。配線断線時にもリレーが落ちるため、フェイルセーフになる。

### 非常停止表示灯

非常停止状態は、機体の外から一目で分かるように表示する。

要件:

- 非常停止中、メインリレーOFF、モータ電源遮断中を表示灯で示す。
- 通常動作可能、待機中、エラー中も色または点滅パターンで区別する。
- 表示灯は中央制御基板から制御する。
- 非常停止の表示はソフト状態だけでなく、可能ならリレー/コンタクタ後段の24V有無も監視して反映する。
- 視認性を優先し、機体上面または側面から見える位置に置く。

推奨表示:

| 状態 | 表示 |
|---|---|
| 非常停止中 | 赤点灯 |
| エラー | 赤点滅 |
| 待機 / 未キャリブレーション | 黄点灯 |
| キャリブレーション中 | 黄点滅 |
| 動作可能 | 緑点灯 |
| 通信断 | 青点滅または赤黄交互 |

非常停止表示灯は、GUIを見なくても安全状態が分かるため必須に近い扱いにする。

## 2-1. 中央制御基板と機体GUI

機体には小型ディスプレーを搭載し、mini PC上のGUIで起動、キャリブレーション、デバッグを行えるようにする。

### 役割

役割分担は以下。

| 要素 | 役割 |
|---|---|
| mini PC | GUI、ログ、設定編集、キャリブレーション操作、デバッグ表示 |
| Teensy | リアルタイム制御、各ユニットへの目標値配信、安全I/O、E-stop監視 |
| 各ユニットMCU | AMT22読み取り、C620制御、ステア/速度ループ |

mini PCはGUIのホストとして使う。TeensyはGUI描画を担当せず、mini PCからの指令を受けて制御系へ反映する。

中央制御基板は以下を担当する。

- Teensyを中心に、各差動ステアユニットへ目標角と目標速を送る。
- 各ユニットの状態をCANで収集する。
- 非常停止、起動許可、エラー状態を管理する。
- mini PCとの通信を行い、GUIへ状態を渡す。
- GUIからのキャリブレーション指令やStart指令を、安全条件を確認したうえで実行する。

### GUIでできること

最低限必要な画面は以下。

| 画面 | 内容 |
|---|---|
| Status | 電源電圧、CAN状態、各ユニット状態、E-stop状態 |
| Calibration | ステア原点合わせ、AMT22ゼロ点保存、ユニットID確認 |
| Start | 起動許可、モータ有効化、制御開始 |
| Debug | 各ユニットの角度、速度、モーターrpm、エラーコード表示 |
| Config | ID、CAN設定、制御パラメータ確認 |

### 操作系

候補:

| 方式 | 特徴 |
|---|---|
| mini PC + HDMI/USB小型ディスプレー | GUIを作りやすく、ログやデバッグ表示に強い |
| mini PC + タッチLCD | 単体操作しやすい。現場向き |
| mini PC + Web GUI | スマホ/ノートPCから確認しやすい |
| Teensy直結OLED | 最小構成の保険。詳細GUIには向かない |

第一段階では、mini PC上で動くGUIを本命にする。Teensy直結OLEDは、mini PCが落ちた場合でも最低限の状態だけ見たい場合の補助表示として扱う。

### GUIの起動シーケンス

```text
電源ON
  |
  |-- mini PC起動
  |-- Teensy起動
  |-- mini PC - Teensy間通信確認
  |-- 各ユニットCAN探索
  |-- ユニットID確認
  |-- AMT22通信確認
  |-- C620通信確認
  |-- E-stop状態確認
  |
  |-- 未キャリブレーションなら Calibration へ
  |-- 問題なければ Standby へ
  |-- Start 操作で Motor Enable
```

### GUIから行うキャリブレーション

最低限、以下をできるようにする。

- 各ユニットの現在角度を表示する。
- ステアを機械的な基準向きに合わせる。
- AMT22の現在値をゼロ点として保存する。
- 保存値を各ユニットMCUの不揮発メモリ、または中央制御側設定に記録する。
- キャリブレーション後に、各ユニットへゼロ点反映を指示する。

### デバッグ表示

デバッグ画面では以下を表示する。

- 各ユニットのCAN通信状態
- 各ユニットの現在ステア角
- 各ユニットの目標ステア角
- 各ユニットの駆動rpm
- 各モーターの指令rpm
- C620フィードバックの有無
- AMT22読取エラー
- E-stop入力状態
- リレー/コンタクタ状態
- バッテリ電圧
- 5V制御電圧
- 12V mini PC電圧

### 安全上の制約

- GUI上のStartだけで即モータ駆動しない。
- mini PC GUIは起動許可を要求するだけで、最終的なMotor Enable判定はTeensy側で行う。
- E-stop解除、通信正常、キャリブレーション済み、エラーなしの条件が揃ったときだけMotor Enableを許可する。
- E-stop中はGUI操作より非常停止状態を優先する。
- Debug画面から直接モーターを動かす場合は、低速・短時間・明示的な確認操作を入れる。
- mini PCが落ちた、またはTeensyとの通信が途切れた場合は、Teensy側で安全停止へ移行する。

## 3. グラウンド設計

### 原則

電位は共通、電流経路は分離する。

```text
中央分電盤のGNDバー = スターの中心
  |-- 6S LiPo (-)
  |-- 各C620の電源(-)       大電流リターン
  |-- 中央DC-DCのGND
  |-- 制御系5VのGND         基準用
```

### 理由

- 全ノードのGNDが共通でないと、CANトランシーバのコモンモード電圧許容範囲を逸脱する可能性がある。
- M3508/C620の大電流リターンが制御GNDを通ると、IRドロップでGNDが揺れる。
- GND揺れはSPI誤読、MCUリセット、CANエラーの原因になる。

### キャリアボードでの実装方針

- C620の大電流GNDと制御系GNDを、基板上で安易に共通ベタにしない。
- モータ電流経路と制御基準経路は、配線レベルで分けて中央分電盤へ戻す。
- 最終的に中央分電盤の1点で合流させる。

## 4. CAN系

### 帯域

1フレームを約125bit、CANを1Mbpsとすると、理論容量は約8000frame/s。

コマンドは `0x200` / `0x1FF` の2フレームに集約する前提。

必要フレーム数の概算:

$$
(N_{motor} + 2) \times 1000
$$

条件:

$$
(N_{motor} + 2) \times 1000 \leq 8000
$$

したがって、

$$
N_{motor} \leq 6
$$

実質的に、1Mbpsの1バスでは3ユニットが上限の目安。

前提:

- エンコーダ角をCANに載せない。
- AMT22は各ユニットMCUで読む。
- 中央へ返すステータスは間引く。
- 4ユニット以上にする場合はCANを2系統に分割する。

### 物理層

- 終端120Ωはバス両端だけに入れる。
- 中央Teensy側と、一番遠いユニット側を終端ONにする。
- 中間ユニットには終端を入れない。
- 各ユニットには120Ωとソルダージャンパを載せ、端ユニットだけONにできるようにする。
- スタブは短くする。コネクタからトランシーバまで数cm以内を目安にする。
- CANクロックは水晶前提。NUCLEO搭載クロックを使う。
- MCUのCAN_TX/CAN_RXをCAN_H/CAN_Lへ直結しない。
- 各ノードにCANトランシーバを1個置く。

### CAN ID設計

| 対象 | ID |
|---|---|
| C620フィードバック | 0x201 - 0x208 |
| C620コマンド | 0x200 / 0x1FF |
| ユニットMCUステータス | 0x300番台など |

方針:

- ユニットMCUのステータスIDはC620帯を避ける。
- ユニットIDは0Ωジャンパ列、またはピンヘッダ＋ジャンパで設定する。
- C620本体のモータIDはC620側DIPで設定する。

## 5. AMT22 / SPI系

### 電圧とレベル変換

AMT22は5Vで駆動する。MCUは3.3V系なので、SPI信号のレベル整合に注意する。

| 信号 | 方向 | 対策 |
|---|---|---|
| SCLK | MCU 3.3V -> AMT22 5V入力 | AMT22のVIH確認後、直結可否を決める |
| MOSI | MCU 3.3V -> AMT22 5V入力 | AMT22のVIH確認後、直結可否を決める |
| CS | MCU 3.3V -> AMT22 5V入力 | AMT22のVIH確認後、直結可否を決める |
| MISO / SDO | AMT22 5V出力 -> MCU 3.3V入力 | 抵抗分圧またはバッファ必須 |

MISOの抵抗分圧:

| 抵抗 | 値 |
|---|---:|
| 上側 | 1.8k |
| 下側 | 3.3k |

出力電圧:

$$
5 \times \frac{3.3}{1.8 + 3.3} = 3.24V
$$

SPI速度は2MHz程度を想定する。抵抗分圧で波形が鈍る場合は、74LVC1G125 / 74LVC1G14 などで受ける。

### SPI注意点

- AMT22はSPIライクだが、CSタイミング、ダミーバイト、チェックビット処理に注意する。
- CSはGPIOで制御する。
- MISOプルアップは基本不要。
- 配線は短くする。

### 未確定

- AMT22のVIHをデータシートで確認する。
- 3.3VがHighとして認識されるなら、SCLK/MOSI/CSは直結でよい。
- 3.3V Highが不十分なら、送信側にもバッファを入れる。

## 6. キャリアボード部品リスト

MCU周りの電源、水晶、デカップリング、BOOT0、NRSTはNUCLEOが内蔵するため、キャリアボード側には不要。

| ブロック | 部品 | パッケージ/実装 |
|---|---|---|
| CANトランシーバ | TCAN332 / SN65HVD230 | SOIC-8 |
| LDO | AMS1117-3.3 | SOT-223 |
| MISO降圧 | 1.8k / 3.3k 抵抗 | 0603以上またはリード部品 |
| CAN終端 | 120Ω + ソルダージャンパ | 手ハンダ可 |
| ID設定 | 0Ωジャンパ列 / ピンヘッダ＋ジャンパ | 手ハンダ可 |
| デカップリング | 0.1uF + 数uF | 手ハンダ可 |
| NUCLEO接続 | ピンソケット | 2.54mm |
| コネクタ | 24V / 5V / GND / CAN / C620 / AMT22 | スルーホール推奨 |

能動ICは実質、CANトランシーバとLDOのみ。

NUCLEOはソケットで抜き挿し可能にする。MCU破損時にNUCLEOだけを交換できるため、現場復旧が速い。

## 7. 開発・実装手順

### 第一段階: NUCLEO搭載キャリアボード

1. NUCLEO-G431KB単体でファームを先行完成させる。
2. AMT22 SPI読み取りを確認する。
3. C620へのCAN指令を確認する。
4. 方位ループと速度ループを実装する。
5. ソフトが固まってからキャリアボードを起こす。
6. キャリアボードに手ハンダ部品を実装する。
7. 実機でCAN、SPI、電源、GNDの問題を確認する。

CANビットタイミングはCubeMXで設定し、制御ロジックは通常コードとして管理する。

### 第二段階: 裸チップ基板

さらに小型化したくなった場合に、同じ回路をSTM32G431K系の裸チップ基板へ移植する。

第一段階の回路、ピン割当、ファーム設計を移植可能な形にしておく。

## 8. 第二段階への移行戦略

### NUCLEOが肩代わりしている回路

第二段階では以下を自作基板側に追加する。

| 機能 | 第一段階 | 第二段階で必要なもの |
|---|---|---|
| 電源デカップリング | NUCLEO内蔵 | VDD各ピンに100nF、10uFバルク |
| VDDAフィルタ | NUCLEO内蔵 | フェライトビーズ、100nF、1uF |
| リセット | NUCLEO内蔵 | NRST-GND間100nF |
| BOOT0 | NUCLEO内蔵 | 10kプルダウン、ジャンパ |
| クロック | NUCLEO搭載水晶 | 8MHz水晶、負荷容量 |
| 書き込み | オンボードST-LINK | SWD 4パッド、外部ST-LINK |

第一段階のうちに、これらを将来追加する前提でドキュメント化する。

### ピン選定

第一段階のピン割当は、NUCLEOの都合だけで決めない。

最初からSTM32G431KのAF表に従って選ぶ。

- FDCAN_TX / FDCAN_RX は、FDCANのAFが出ているピンから選ぶ。
- SPI SCLK / MISO / MOSI は、同じSPIペリフェラルで揃うピン群から選ぶ。
- CSはGPIOでよい。
- MISOは5Vトレラントピンを狙う。
- IDジャンパやステータスGPIOは、CAN/SPIの専用機能ピンを避ける。

これにより、第二段階でCubeMXのピン定義やファームのピンマクロを変更せず移行しやすくなる。

### ファーム設計

NUCLEO固有機能に依存しない。

- オンボードST-LINKに依存しない。
- NUCLEOのLEDやユーザーボタンに依存しない。
- NUCLEO固有のBOOT制御に依存しない。
- デバッグ表示はUARTまたはCANログに寄せる。
- SWDは自前パッドと外部ST-LINK前提にする。

### キャリアボード側の仕掛け

- シルク印字とネット名は、NUCLEOコネクタ番号ではなく `PAx` / `PBx` のピン名で統一する。
- KiCad上では、論理的にSTM32G431Kのピン名で配線を管理する。
- 第二段階で追加する定石部品は、未実装ランドとして置くか、少なくとも回路図メモに残す。
