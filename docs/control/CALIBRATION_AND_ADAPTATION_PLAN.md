# キャリブレーション拡張と負荷適応の将来計画

作成: 2026-07-06(状態: **将来計画**。実装未着手)

## 背景・動機

- ゲイン調整はタイヤを浮かせたベンチで実施中。接地するとスクラブトルク(接地荷重比例)が
  乗り、ブレークアウェイ電流が浮き実測(150〜950 raw)から大きく変わる。
- カスケード構造のため角度ループ(angle_kp等)は接地後もほぼ流用可。変わるのは
  電流系3点: `current_limit` / `mode_integral_limit` / `steer_min_rpm`。
- この3点は実測値から固定式で導出できる。つまり**特性化を自動化すれば、重量・床が
  変わってもキャリブレーション再実行だけで追従できる**。
- ユニット抽象化(`docs/ARCHITECTURE_DECISIONS.md`)には最初から
  「キャリブレーション指令/状態」が定義済み。現想定のゼロ点調整に**機構特性の自己同定**を
  追加する位置づけで、アーキテクチャ変更は不要。
- 電流ランプによるブレークアウェイ特性化アプリは実装済み(2026-07-05、手動ベンチツール)。
  これをCALシーケンスへ再構成する。

## キャリブレーションフロー案(ユニット単体で完結)

前提条件(オペレータが保証): 接地・静止・周囲クリア。中央からCAL開始指令1本で実行。

```text
1. センサ健全性チェック(AMT22応答・チェックビット、C620フィードバック鮮度)
2. 操舵ブレークアウェイ同定: 電流ランプを両方向 × 数角度
   → 最悪値B、方向非対称、角度ムラを記録
3. 小振幅rpmステップ → 立ち上がり時定数 → 実効イナーシャ(将来LESOのb0)
4. パラメータ導出(固定式):
   current_limit     = clamp(2×B, 下限, HARD_MAX)
   mode_integral_limit = 1.25×B 程度(Bとcurrent_limitの間)
   steer_min_rpm     = スティックスリップ帯の実測から
5. Flash保存(ゼロ点と同じCRC付き領域)+ CAL結果を中央CANへ配信
失敗条件: HARD_MAXまで上げても不動 / 角度が想定外に変位 → エラー状態で停止
```

## 設計ルール

1. **安全上限(HARD_MAX)は自動化しない。** ファームにハードコードし、引き上げは
   ユーザー承認事項のまま残す。校正ルーチンの暴走で上限が上がる経路を構造的に塞ぐ。
2. **角度依存は数点サンプリングの最悪値**で決める(浮き実測で角度ムラが大きいことは確認済み)。
   全周スイープは所要時間とタイヤスクラブ摩耗と相談。
3. **駆動側の同定はCALフェーズに含めない。** 操舵CALは接地でその場実行できるが、
   駆動ランプは車体が動く。駆動側は低速走行試験で別途。

## 負荷適応のロードマップ(CALとLESOは補完関係)

| 手段 | 適応の速さ | 役割 |
|---|---|---|
| CALフェーズ(本計画) | 遅い(明示的に再実行) | 環境が変わった時の再特性化。安全境界(limit系)の決定はこちらのみ |
| LESO/LADRC(将来) | 速い(実行中連続) | 走行中の荷重移動・床の継ぎ目などCALで追えない変動の打ち消し |

段階:

1. **接地での手動再特性化 + PI再調整**(既存ツールのまま。実車を動かす最短路)
2. **CALフェーズ拡張**(本計画のフロー実装。ゼロ点CALと統合)
3. **LESO導入判断**: 実走で「加速中だけ操舵が重い」等の荷重変動症状が観測されたら、
   操舵モードPIをLESO(拡張状態オブザーバ)ベースへ置き換え。b0はCAL手順3の同定値。
   制約は2点——スティクション非線形は消えない(min_rpmフロアは残る)、
   C620 rpmノイズ(静止±50rpm)がオブザーバ帯域を制限(ω_o=30〜80rad/s目安から)。
