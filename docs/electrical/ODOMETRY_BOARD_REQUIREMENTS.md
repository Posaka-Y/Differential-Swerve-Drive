# オドメトリ基板(STM32G474)要件

## 目的

3輪オドメトリ(磁気エンコーダ x3、測定輪)を読み取り、基板上でx/y/θを積分して中央CANへ配信する専用ノード。unitId=4。

> **センサ変更(2026-07-06確定)**: AMT102 x3(クアドラチャ)を廃止し、**I2Cホール(磁気)エンコーダ x3**へ変更。
> 第一候補**MT6701**(14bit、INL小、I2C/SSI/ABZ選択可)、代替AS5600(12bit、INL±1〜2°)。
> 理由: センサ費が約¥9,000→¥1,000〜1,500。オドメトリは相対移動の積分なのでAMT102の
> 速度品質優位より価格差を優先。
>
> **基板の実現方式(自作 or 購入ボード)は未確定**。ユニット基板のMatek CAN-G474採用可否
> (ベンチ試験後に判定)と合わせて決める。以下の要件・ピン割当は自作G474RET6基板を想定した正本。

## 方針

- MCUはユニット基板と同じ**STM32G474RET6(LQFP64)**。BOM・KiCad共通ブロック・ファームのplatform層を共通化する。
- 外部接続はユニット基板と同じ**4線ハーネス(COMM_A/B + 5V + GND)、JST XH**。中央から見ると「x/y/θを流してくる高レベルCANノード」で、駆動ユニットと同じ抽象化。
- MCU最小構成・中央CANブロック・電源ブロックは `CARRIER_BOARD_REQUIREMENTS.md` と共通(KiCadブロック流用)。C620用FDCAN2は載せない(または将来用にDNPフットプリントのみ)。

## 磁気エンコーダ入力 x3(I2C)

| 項目 | 内容 |
|---|---|
| センサ | MT6701(第一候補)/ AS5600(代替)。搭載済み小基板モジュールを使用 |
| 電源 | 3.3V(基板のLDOから)。3個で数十mA |
| バス構成 | **I2Cバス3本に1個ずつ分離**(AS5600はアドレス固定0x36のため。MT6701でも配線・故障切り分けが単純になる) |
| プルアップ | 各バスSCL/SDAに2.2kΩ(モーターノイズ環境のため強め)。センサモジュール側の実装済みプルアップと重複しないよう確認 |
| クロック | 400kHz(Fast-mode)。角度2バイト読み x3 は1kHz周期に余裕 |
| 配線長 | センサ→基板30cm以内を目安。ツイスト or GND並走 |
| バスリカバリ | **ファーム必須**: バスハング検出時にSCLを手動トグル(9クロック)して解放、その後再初期化。健全性カウンタをSTATUS3で配信 |
| 磁石 | 径方向着磁(φ6×2.5mm等、センサ指定品)。ギャップ1〜3mm、軸ズレ許容約0.25mm。測定輪軸端に磁石ホルダー、センサ基板マウントをCAD側で設計 |
| アンラップ | シングルターン絶対角をソフトで連続化。サンプル間半回転未満が条件(1kHzなら余裕) |

I2Cバス・ピン割当(ST公式ピンデータで2026-07-06成立確認済み):

| センサ | バス | SCL | SDA |
|---|---|---|---|
| Wheel 1 | I2C1 | PA15 (AF4) | PB7 (AF4) |
| Wheel 2 | I2C2 | PA9 (AF4) | PA8 (AF4) |
| Wheel 3 | I2C3 | PC8 (AF8) | PC9 (AF8) |

共通部(ユニット基板と同一割当): FDCAN1=PA11/PA12、デバッグUART=PA2/PA3、LED=PA5/PB10/PB11、SWD=PA13/PA14、HSE=PF0/PF1、BOOT0=PB8。

**ユニット基板との差分に注意**:

- ID: 共通マップのPC6/PC7/PC8はPC8がI2C3_SCLと衝突するため、本基板では**PB13/PB14/PB15**へ移す(FDCAN2・AMT22 SPIが無いので空き)。またはFlash保存のunitIdで代替しジャンパ省略も可。
- 5V監視ADC: PA0が空いているのでユニット基板と同じPA0のまま使える(AMT102案で必要だったPC0への移動は不要になった)。

## ファーム要件

- 3センサの角度を固定周期(1kHz)で読み、差分から輪速へ変換、3輪オムニの順運動学でvx/vy/ωへ変換、x/y/θを積分する。
- I2C読み取りはバスごとに独立処理し、1バスの障害が他輪の読取を止めない構造にする。読取失敗はその周期の当該輪を前回値ホールド+エラーカウント。
- ホイール配置(半径、取付角、車体中心からの距離)と磁石オフセットは`UnitConfig`としてFlashに保存し、SET_CONFIGで書き換え可能にする。
- 座標系は+X前/+Y左/+θ反時計(CCW)。θは折り返さず連続値で保持する。
- 配信: STATUS1/2(pose)を100Hz、STATUS3(健全性: I2Cエラー/リカバリ回数含む)を10Hz(`COMMUNICATION_NAMING_AND_IDS.md`参照)。
- `ODOM_RESET`(UNIT_CTRLサブコマンド0x10)で原点リセット。

## 検証

1. 1輪だけ接続し、手回しで角度の連続性(アンラップ)、回転方向の符号、1回転で360°を確認。
2. 磁石ギャップ・軸ズレを振って読み値の劣化(MT6701はステータスbit)を確認し、マウント公差を決める。
3. 3輪接続し、車体を既知距離だけ直進・並進・回転させてx/y/θの誤差を測る。
4. モーター通電状態でI2Cエラーレートを測る(バスリカバリの発火回数をSTATUS3で監視)。

## 旧案(AMT102 x3、2026-07-06廃止)の記録

クアドラチャ x3をTIM2/TIM3/TIM4のEncoder Modeで読む案。タイマHWカウントでノイズ耐性・
CPU負荷の面では優れるが、センサ費約¥9,000が磁気エンコーダの約6〜9倍のため不採用。
I2Cの信頼性が実機で問題になった場合の差し戻し先として、タイマ割当案
(TIM2=PA0/PA1、TIM3=PA6/PA7、TIM4=PB6/PB7、5V監視をPC0へ移動)をここに残す。
MT6701はABZ出力も持つため、センサを変えずにクアドラチャ読みへ切り替える中間案もある。
