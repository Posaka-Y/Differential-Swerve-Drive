# 中央制御ボード(Teensy 4.1)要件

## 目的

Teensy 4.1を載せる中央制御ボードをKiCadで設計する。

設計方針: **本プロジェクト専用にしすぎず、後輩・後続プロジェクトで再利用できる汎用CANマスタボードにする。** CAN 2〜3系統とI2C/UART/SPI/GPIOの拡張ヘッダを持ち、安全I/O(E-stop、コンタクタ制御)だけが本プロジェクト固有の色になる。

## 役割(SYSTEM_ARCHITECTUREより)

- 駆動CANで各ユニットへ目標値配信、状態収集
- センサーCANでオドメトリ/IMU状態推定ノードを収容
- I2Cでバッテリー電圧・電流監視を収容
- E-stop監視とMotor Enable最終判定
- コンタクタコイル制御
- mini PCとのGUI通信

## Teensy 4.1の前提

| 項目 | 内容 |
|---|---|
| ロジック電圧 | 3.3V。**5VトレラントではないのでGPIOに5V以上を直接入れない** |
| CAN | FlexCAN 3系統(CAN1/CAN2/CAN3)。CAN3のみCAN FD対応。トランシーバは非搭載なので基板側に必要 |
| USB | micro USBネイティブ(USB-CDC)。mini PCとの接続に使う |
| 電源 | VIN 3.6〜5.5V。**外部5V給電とUSB接続を併用する場合、裏面のVUSB-VINパッドを必ずカットする**(切らないとPC USBと5V系が衝突する) |

## mini PC接続(2026-07-02決定)

第一候補: **Teensyネイティブのmicro USB(USB-CDCシリアル)**。

mini PC本体はGMKtec NucBox G2を採用する(2026-07-19)。G2は常時通電12V制御系から給電し、E-stopでモータ主電源を落としてもUSB-CDC通信、GUI、ログ、故障表示を維持する。

- 追加ハードウェア不要、転送量もGUI/ログ用途に十分。
- CAN-to-USB(CANable等)をGUI主回線にする案は不採用。GUIトラフィックが安全系バスに乗る・アダプタと独自プロトコルが増えるため。
- ただしCANableはCANバスの監視・デバッグツールとして有効なので、各CANに監視可能なGHコネクタまたはテストポイントを設ける。

## CAN

| 系統 | 用途 | トランシーバ |
|---|---|---|
| CAN1 | 駆動CAN(ユニットx3、Classic CAN 1Mbps) | `TCAN1051VDRQ1` |
| CAN2 | 汎用拡張/デバッグ/予備 | フットプリント実装、初期BOMはDNP可 |
| CAN3 | センサーCAN(オドメトリ/IMU、Classic CAN 1Mbps) | `TCAN1051VDRQ1` |

要件:

- 各CANに`RC0603FR-07120RL` 120Ωと`JS102011SAQN`スライドスイッチによる終端を実装する。中央基板が物理端ならON、各バスの最遠ノードでもう1個をONにする。
- 各CANに`ESD2CAN24DBZRQ1`を実装する。
- CANコネクタはJST GH 3pin(COMM_A / COMM_B / GND)。電源コネクタと分離し、CANをデイジーチェーン接続する。
- CAN共通回路、正式型番、配置制約は`CAN_COMMON_BLOCK_PART_SELECTION.md`を正本とする。

## 安全I/O(本プロジェクト固有部分)

| 信号 | 回路 |
|---|---|
| `ESTOP_N` 入力 | E-stopスイッチのNC接点ループを監視。24V系ループを使う場合はフォトカプラまたは分圧+クランプで3.3V化。**Teensyに生の24Vを入れない** |
| `MOTOR_PWR_EN` 出力 | 所有済みリレーを介してモーター主電源系を操作する。リレー型番・コイル/入力仕様を確認後、GPIO直結不可ならMOSFET等の駆動段を設ける |
| `MOTOR_PWR_SENSE` 入力 | 24Vモータバスの有無検出。分圧(例: 100k/10k)+クランプでADCへ |
| 表示灯出力 | 赤/黄/緑(+予備1)。表示灯が24V系ならMOSFETローサイド駆動 |

E-stopのNC接点はコンタクタコイル電源ループに**ハードワイヤで直列**が主経路であり、Teensyの監視は従。ソフトが死んでもE-stopは効く構成を維持する(POWER_DISTRIBUTION_AND_ESTOP.md参照)。

- E-stopは2個とし、NC安全接点を直列接続する。監視入力は最低限ループ全体を監視し、個別診断が必要なら各ボタンの補助接点を追加する。
- コンタクタコイル用ローサイドMOSFET、Gate pulldown、サージクランプを中央基板へ実装する。Teensy未起動時の既定状態はOFFとする。
- `MOTOR_PWR_EN`は遠隔停止にも使用する。停止指令、通信監視異常、Teensy安全状態遷移で直ちにOFFとし、停止原因をラッチする。再投入は独立した明示的な再アーム操作でのみ許可する。
- 可能ならコンタクタ補助接点、またはモータバス電圧の`MOTOR_PWR_SENSE`により、OFF指令後に実際に主接点が開いたことを診断する。溶着疑いは再アーム禁止故障とする。
- E-stop内蔵24V LEDは中央基板のGPIOで駆動せず、`24V_CTRL`と各ボタンの独立補助接点でハードワイヤする。中央基板には必要に応じてヒューズ付き`24V_CTRL`入出力端子を設ける。
- 所有品はKILIGEN `E228`、24V DC、100A表記と判明したが、販売情報上の連続使用目安は50〜60Aで、24V DC負荷遮断定格を示す正式データシートを確認できない。このためメインコンタクタには採用せず、中央基板のコイルドライバは別途選定するコンタクタのコイル電流、内蔵サージ素子、必要解放時間に合わせて確定する。

## 外部状態表示LED

- 独立した安全表示灯用に赤/黄/緑(+予備)の24V対応ローサイド出力を設ける。
- テープLEDは方式未確定のため、初版では電源を直接基板へ大電流で通すのではなく、ロジック出力と外付けLEDドライバ用コネクタを基本案とする。
- アドレサブルLED候補に備え、5Vレベル変換済みデータ出力1〜2chとGNDを引き出せる構成を検討する。
- 24V RGBテープを採用する場合は、各色の負荷電流に合わせた外付けMOSFETドライバを使う。
- LED用電源分岐は個別ヒューズとし、最大電流をコネクタおよびシルクへ明記する。

## 再利用性のための拡張ヘッダ

外部コネクタはJST GHを基本とし、シルクに信号名を明記する。

| 拡張 | 数 | 備考 |
|---|---|---|
| I2C | 2系統(Wire/Wire1) | 1系統をバッテリー電圧・電流監視に使用。プルアップ抵抗のフットプリント付き(ジャンパで切離し可) |
| UART | 2系統 | TX/RX/GND |
| SPI | 1系統 | CS用GPIO 2本付き |
| GPIO/ADC | 8本程度 | 3.3Vロジック注意のシルク表記 |
| 電源出力 | 5V / 3.3V / GND | 拡張デバイス給電用(合計電流に上限表記) |

## 電源

- 入力: 購入済み24V→5V/5A DC-DCから5V。主入力コネクタはXT30等の5A対応品。
- 中央基板上でTeensy、ユニットx3、オドメトリ/IMU基板へ5V/GNDをスター分配する。G474ノード4枝は`1206L050/15YR`で個別保護し、PPTC後に`LTST-C190KGKT`+1.5kΩの電源表示とテストポイントを設ける。Teensy/拡張枝は負荷実測後に別定格を選定する。
- Teensy VINへ5V直結。3.3VはTeensy内蔵レギュレータ(外部負荷は250mA程度まで)。拡張デバイスの3.3V消費が増える場合は基板に3.3V LDOを追加。
- 5A主入力の逆接/逆流保護は未選定。1.5A定格の`LM66100DCKR`は中央主入力には使用しない。

## チェック項目

- [ ] VUSB-VINパッドカットを組立手順に明記した
- [ ] Teensyに5V以上が入る経路がない(E-stop、SENSE、表示灯)
- [ ] 中央CAN終端がボード上にあり、`TERM ON/OFF`スライドスイッチで切れる
- [ ] バス監視用の分岐コネクタがある
- [ ] 拡張ヘッダのシルクに信号名と3.3V注意がある
- [ ] コネクタピン配置がユニット基板と統一されている
