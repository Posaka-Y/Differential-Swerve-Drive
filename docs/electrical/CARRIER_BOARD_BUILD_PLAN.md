# ユニット基板・中央ボード 製作計画

## 参考ボード方針(2026-07-06)

基板製作は、購入済みのMatek CAN-L431と、Matek CAN-G474、ARK CANnode、CANable 2.0を参考に進める。参照範囲と相違点は`CARRIER_BOARD_REQUIREMENTS.md`の「参考ボードと利用範囲」を正本とする。

- CAN-G474実機を主試験機とし、G474、2系統CAN、電源、コネクタおよびカスタムファームを検証する。
- CAN-L431実機は1Mbps CANの配線、終端、コネクタ、対向ノード試験に使う。
- NUCLEO-G474REはCAN-G474で書込み・復旧・必要I/Oに問題が出た場合と、現行ピン設定の回帰確認に使う。
- ARK CANnodeとCANable 2.0は公開回路/BOMから電源、MCU最小構成、CAN、SWD、保護回路を比較する。
- 参考基板と本基板ではMCUパッケージ、CAN系統数、用途、ノイズ環境が異なるため、回路ブロックごとにデータシートで成立性を確認する。

## 共通設計ブロック方針(2026-07-02)

ユニット基板(G474)と中央ボード(Teensy 4.1)は、KiCadの階層シートで共通ブロックを共有する。

| ブロック | 内容 | 使用箇所 |
|---|---|---|
| `can_interface` | `TCAN1051VDRQ1` + `ESD2CAN24DBZRQ1` + 120Ωスライド終端。中央CAN外部接続は横挿しGH 3pin x2(COMM_A/B/GND)、電源は別GH 2pin | ユニット2箇所、中央1〜3箇所 |
| `power_input_5v` | 5V入力 + 逆接保護 | ユニット、中央 |
| `status_led` | 状態LED x3 | ユニット、中央 |
| MCU最小構成 | G474+水晶+SWD+BOOT0(CANable流用) | ユニット。将来の汎用G474 CANノードに転用可 |

リポジトリ構成案:

```text
hardware/
  lib/             共通シンボル・フットプリント
  blocks/          共通階層シート
  unit-board/      G474ユニット基板
  central-board/   Teensy 4.1中央ボード
```

- 共通ライブラリ・ブロックはgit管理し、後続プロジェクトから流用できるようにする。
- 発注はユニット+中央の異種面付けを検討する(製造1回で全基板)。

## フェーズ0: ピン割当確定

やること:

- 主試験機はMatek CAN-G474、NUCLEO-G474REは予備(2026-07-06)。最終搭載はG474RET6自作基板のまま変更しない。
- AF表でFDCAN1(中央CAN)とFDCAN2(C620 CAN)のTX/RXを決め、morphoコネクタに出ていることを確認する。
- SPI SCLK/MISO/MOSIを同じSPIペリフェラルで揃える。
- AMT22は全信号3.3V直結でよい(要件ドキュメント参照)。5Vトレラント要件は不要になった。
- CS、IDジャンパ、LED、デバッグ用GPIOを割り当てる。
- CAN-G474のhwdef(CAN1=PA11/PA12、CAN2=PB5/PB6、SPI2=PB13/PB14/PB15、CS=PB12)と、NUCLEO-G474RE用の現行割当をボード別設定として管理する。

完了条件:

- CubeMXでピン割当が成立する。
- 第二段階の裸チップでも同じピン割当が使える。

## フェーズ1: ブレッドボード / 手配線検証

やること:

- Matek CAN-G474へカスタムファームを書き込み、CAN1/CAN2を同時に1Mbpsで動作させる。
- Matek CAN-L431を中央CANの対向ノードとして接続し、極性、1Mbps通信、終端抵抗、エラーカウンタを確認する。
- NUCLEO単体でAMT22をSPI読み取りする。
- NUCLEOからC620_CANトランシーバ経由でC620通信する。
- 中央CANトランシーバ経由でTeensyとの通信を確認する。
- IDジャンパ読み取りを確認する。
- 5V、3.3V、GNDの安定性を確認する。

完了条件:

- CAN-G474のCAN 2系統が同時に安定動作し、CAN-L431との1Mbps通信、終端・配線条件を記録できる。
- AMT22角度が読める。
- C620 x2へ指令が出る。
- C620フィードバックが読める。
- 低速でステア/駆動が動く。

## フェーズ2: 回路図作成

ブロック:

- STM32G474RET6 + 最小構成(水晶、デカップリング、VDDA、NRST、BOOT0、SWD)
- 中央CANトランシーバ
- 中央CAN終端(`JS102011SAQN`スライドスイッチ、末端ユニットのみON)
- C620_CANトランシーバ
- C620_CAN終端
- TVS(`ESD2CAN24DBZRQ1` x2)
- AMT22コネクタ(全信号直結。分圧なし)
- LDO
- IDジャンパ
- 状態LED、テストポイント
- 電源入力
- COMM_A/COMM_B/VIN_CONTROL/GND_CTRL 4線ハーネスコネクタ

回路図ルール:

- ネット名は `PAx` / `PBx` を基準にする。
- COMM_A/BとC620_CAN_H/Lを混同しない。
- MCUのC620_CAN_TX/RXをC620_CAN_H/Lへ直結しない。
- 制御GNDと大電流GNDの扱いを明記する。

## フェーズ3: PCB設計

注意:

- 中央CANトランシーバを外部通信コネクタ近くに置く。
- C620_CANトランシーバをC620側コネクタ近くに置く。
- C620_CANスタブを短くする。
- LDOとトランシーバのデカップリングを近くに置く。
- MCUのデカップリングは各VDDピン直近に置く。水晶はMCU直近・短配線・GNDガード。
- SWDヘッダは組付け後もアクセスできる位置に置く。
- AMT22のSPI配線を短くする。
- 終端ジャンパのON/OFF状態がシルクで分かるようにする。
- IDジャンパのビット意味をシルクで分かるようにする。

## フェーズ4: 初回実装

初回は全機能を一気に載せず、段階的に確認する。

1. 電源系だけ実装して5V/3.3V確認。
2. MCU+最小構成を実装し、SWDでDevice ID認識 → LED点滅で起動確認。
3. 中央CANトランシーバを実装してTeensyとの通信確認。
4. C620_CANトランシーバを実装してC620通信確認。
5. AMT22まわりを実装してSPI確認。
6. IDジャンパを確認。
7. C620 x2と接続して低速動作確認。

## フェーズ5: 実機検証

ログ項目:

- 5V電圧
- 3.3V電圧
- 中央通信エラー
- C620_CANエラー
- AMT22読取エラー
- C620フィードバック有無
- モーターrpm指令
- ステア角
- ユニットID

合格条件:

- 起動時に全ユニットIDが識別できる。
- 各ユニットのAMT22が読める。
- 各C620が応答する。
- E-stop時にモーター電源が遮断される。
- 通信断時に安全停止へ移行する。
