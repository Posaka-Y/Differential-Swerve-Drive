# 中央基板 Rev.1 設計憲法

> **2026-09-23最終方針**: 専用CANは横挿しGH3（A/B/GND）。駆動/ODOMのCAN2pin案は撤回。コイルdriverは中央搭載。主接点専用監視は付けずC620 CAN応答を補助診断とする。最新の[一括発注計画](PCB_BATCH_V2_CENTRAL_PLAN.md)を優先し、本文の旧CONTACTOR_STATUS_N案は採用しない。


作成: 2026-09-12
位置づけ: 中央基板(Teensy 4.1)の最上位設計方針。**ここに書いた内容は他のどの中央基板ドキュメントより優先する。** 個別の部品選定・回路詳細は`CENTRAL_BOARD_REQUIREMENTS.md`、ピン割当は`TEENSY41_CENTRAL_PIN_ASSIGNMENT.md`、回路図正本は`CENTRAL_BOARD_SCHEMATIC_REFERENCE.md`。矛盾する場合は本ファイルを正とし、該当ドキュメントを更新する。

## 狙い

今のロボットで使えるだけでなく、**後輩が別のロボットでも再利用しやすい中央基板**にする。ただし万能基板にはしない。

## 最上位ルール

> **USBだけでも開発でき、24Vを入れれば実機運用でき、24V+USBでは実機を動かしながらデバッグできる。**

| 状態 | Teensy | 通信/センサ | 24V負荷 | USBデバッグ |
|---|---:|---:|---:|---:|
| USBのみ | ○ | ○(USB供給能力内) | × | ○ |
| 24Vのみ | ○ | ○ | ○ | × |
| 24V + USB | ○ | ○ | ○ | **○** |

24V+USB時は原則**24V由来5Vで基板を駆動し、USBは通信・書込み用途**とする。USB側と基板5V側は逆流させない(電源切替/ORing)。

**5V設計目標は5A級。** 想定最大3〜4Aならレギュレータを4Aギリギリにしない。

## Teensy / 通信

- メインMCUはTeensy 4.1。通信はCANを主役にし、ロボット内の分散基板はなるべくCANノード化する。
- CAN系統はDrive / Sensors・IO / Expansionの用途分離を維持する(既存のCAN3 Drive FD / CAN1 Sensor / CAN2 Expansionと整合)。
- UART/SPI/I2Cは必要数だけ外部へ出す。**「いつか使うかも」で全GPIOをコネクタ化しない。**

## 汎用ポート(2026-09-12、適用範囲を限定して確定)

再利用性のため、汎用拡張ポートを新設する。**このポートに限り**5V/GND/CANH/CANLを4pin一体のコネクタにする。

```text
5V
GND
CANH
CANL
```

**適用範囲: この4pin一体ポートは新設の汎用CAN拡張ポートだけに使う。** 既存のユニット基板・オドメトリ基板への内部ハーネスは、2026-07-17確定の「電源とCANを分離する」方式(GH2電源 + GH3 CANの分離・デイジーチェーン)を維持する。汎用ポートと内部ハーネスは別物として扱い、混同しない。

加えて少数の汎用I/Oポート(5V/GND/GPIO×2、PWM/ADC兼用)を用意する。特殊用途が出たら中央基板を改造せず子基板を追加する。

## 24V負荷制御(2026-09-14に方針撤回。下記は旧版メモ)

**この節は撤回済み。** 電磁弁・リレー・ソレノイド・ブザー等の汎用24V/12V機器駆動は独立CANノードへ切り出す。メインコンタクタだけは例外で、別体`CONTACTOR_DRIVER`へ中央Teensyの3.3V `MOTOR_PWR_EN`を直接渡す。中央基板には汎用N-MOSローサイド出力もコイルMOSFETも搭載しない。詳細は`docs/ARCHITECTURE_DECISIONS.md`を参照。以下は2026-09-12時点の旧方針(参考として残す):

**2026-07-20確定の「Rev.A中央基板に汎用24V負荷出力を増設しない」を撤回する。** 汎用N-MOSローサイド出力を数ch、中央基板に搭載する。

用途: コンタクタコイル、電磁弁、リレー、ソレノイド、ブザー等。

```text
+24V
  │
 LOAD
  │
  ├── Flyback / TVS
  │
 N-MOS
  │
 GND
```

MOSFETは60〜100V耐圧を基本に、Teensyから制御可能な構成にする。**モータや大電流LEDなどの数A〜数十A負荷は中央基板に背負わせない**(モータドライバ・大電流LEDドライバ・バッテリ充電回路は載せない)。

## E-STOP / コンタクタ

**2026-09-17境界修正: コンタクタのコイルMOSFET励磁回路は中央PCBにもCANノードにも置かず、別体`CONTACTOR_DRIVER`として使う。** 中央基板は非常停止ボタン2個の集約・絶縁監視(LTV-847S)に加え、Teensyの`MOTOR_PWR_EN` 3.3V ON/OFFをdriverへ直接出力する。ハードNCループもdriverまで物理配線し、CAN指令をコンタクタ励磁の直接経路にしない。詳細は`docs/ARCHITECTURE_DECISIONS.md`の「コンタクタ励磁」を参照。

- メインコンタクタは既存確定の**KILIGEN E228**を継続する(2026-07-26の実績データ・コイル仕様をそのまま使う。TN686は本憲法内では一般名として使っただけで、部品変更ではない)。
- 主電源遮断経路:

```text
Battery ── E228 MAIN CONTACT ── Motor Power Bus
```

- コイル制御経路(旧: 中央基板内で完結。新: E-STOP NCまでが中央基板、以降はノード基板側):

```text
24V ── Fuse ── E-STOP NC(物理、中央基板でループ集約) ── E228 Coil ── MOSFET(別体CONTACTOR_DRIVER) ── GND
Teensy MOTOR_PWR_EN 3.3V ON/OFF ── driver gate buffer ── MOSFET gate
```

- コンタクタON条件: `E-STOP OK ∧ MOTOR_PWR_EN=High`。**E-STOPはソフトウェアを介さず直接コイル回路を切る。** `MOTOR_PWR_EN`はCANノードを介さず中央Teensyから別体driverへ直結し、reset/Hi-Z時はpulldownでMOSFETをOFFにする。
- E-STOP解除後の自動再起動は禁止。再度ENABLE操作を要求する(既存の再アーム要件と整合)。
- E-STOPの補助接点をTeensyにも入力し`ESTOP_STATE`として監視する(既存のLTV-847S監視と整合)。

## Fail-safeルール

- 電源投入直後は危険な出力を全部OFF。MCU Reset、GPIO Hi-Z、Firmware crash、CAN lossなどでコンタクタや電磁弁が勝手にONにならない回路にする。
- MOSFETゲートにはハードウェアプルダウンを入れる。
- 起動シーケンス: `Power ON → MCU boot → Self check → E-stop確認 → ENABLE command → Contactor ON`

## デバッグ性(Rev.1で妥協しない)

**USB一本で最低限の基板単体試験ができること。** 24Vなしでも: Teensy起動、ファーム書込み、USB Serial、GPIO確認、通信確認、可能な範囲のCAN試験ができる。24V+USBなら実機を完全動作させながらPCからログ・書込み・デバッグ可能。

テストポイント最低限: `24V / 5V / 3.3V / GND / CANH / CANL`。

LEDは最小限: **5V POWER / 24V POWER / STATUS / FAULT** 程度で十分(2026-09-12午前に検討したポート単位のアクティビティLED拡張よりも、この最小セットを優先する)。

## 保護

- 24V入力: ヒューズ → 逆接保護 → TVS → Buck、を基本とする。
- 5V側は大電流になるため、細い信号配線ではなくプレーン/ポリゴンで配電する。
- CANは終端抵抗をジャンパ等で有効/無効にできるようにする(既存のTERM ON/OFFスライドスイッチ方式と整合)。

## Rev.1で「やらないこと」

- モータドライバを載せない
- 大電流LEDドライバを載せない
- バッテリ充電回路を載せない
- 全部のセンサ専用回路を載せない
- 無限にGPIOを増やさない
- Ethernet等を「いつか使うかも」で追加しない
- 高機能な電源監視を際限なく追加しない

必要になったらCAN子基板で対応する。

## Rev.1終了条件

これを全部満たしたら機能追加をやめて発注する。

1. USBだけでTeensyが起動・書込み可能
2. 24Vだけで通常運転可能
3. 24V+USBで実機デバッグ可能
4. 24V→5Vが想定最大3〜4Aを余裕を持って供給
5. 必要なCAN系統が動作
6. E-STOPがMCU非依存でE228を遮断
7. TeensyからE228を遠隔ON/OFF可能
8. 数chの汎用24V負荷を制御可能
9. 必要最低限の汎用I/Oを持つ
10. 電源/CANのテストポイントがある

## 設計順

電源入力・USB電源共存 → 24→5V Buck → Teensy電源 → CAN → E-STOP/コンタクタ → 汎用MOS出力 → その他I/O

## 電源実装の確定事項（2026-09-14に再修正）

- **2026-09-12確定の「24V→5V Buckを中央基板に内蔵する」を撤回する。** 既存の購入済み外部24V→5Vモジュール(`SD-25B-5`、5.00V封印)で降圧済みの5Vを中央基板の主入力とする(旧方式に復帰)。
- 中央基板側はXT30(5V入力)→TI `TPS259470LRPWR` eFuse以降を担当する。定数は`CENTRAL_BOARD_REQUIREMENTS.md`を正本とする。
- まだ決めていないのは、USB優先ORing、入力ヒューズ定格、LiPo低電圧遮断の責務分担である。
